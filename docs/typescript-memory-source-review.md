## Integration decision

| Requirement | pi-optchat | optchat-durable |
| --- | --- | --- |
| Own existing TypeScript agent/model loop | Reuse/extract `Memory` + `Store`, implement `Compressor` callback | Adopting public SDK also adopts Pi Durable task/conversation runtime |
| Supported published library API | No `main`, `types`, or `exports`; distribution is Pi extension with `.ts` sources | Public JS + declarations, explicit exports, documented SDK |
| Provider independence | Memory core takes `(input, AbortSignal) => Promise<string>`; Pi compressor is separate | Custom Pi `Models` providers accepted; not a plain arbitrary summarizer callback |
| External storage | `Store` interface permits async writes, images, optional lease | Pi `Storage` and native transactions/documents/tasks |
| Runtime portability | Node events/fs/Buffer; core not browser-native | Node >=22.19, Pi Durable + Chord; standalone uses native SQLite writer lock |
| Integrating without Pi | Small extraction/packaging effort, plus correctness/observability hardening | Pure tree utilities reusable; extracting durable execution would be substantial redesign |
| Existing Pi Durable application | Extra extension integration | Natural public SDK path |

The strongest candidate for a small independent TS memory library is pi-optchat's **core**, not its full npm extension. The strongest candidate if the new project deliberately adopts Pi Durable is optchat-durable's **supported SDK**. Neither should be represented as a drop-in replacement for our existing diagnostics and policy without extra qualification. Sources: [pi core](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/memory.ts), [pi storage](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/store.ts), [durable SDK contract](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/docs/guides/sdk.md).

## Execution and failures

**pi-optchat:** microtask scheduler, default eight concurrent jobs; starts among the first eight unfinished leaves, then ready parents. Short sources <=512 UTF-8 bytes are copied without a model. Core trusts any nonempty trimmed compressor result. Core failure retries are indefinite with a default ten-second delay and warn once per node. The supplied Pi compressor separately tries up to five size rewrites, picks shortest complete response and may return an oversized/nonshrinking result after exhausting attempts. `settle('turn')` resolves when ready **or stalled on failures**; render then includes `(not summarized yet: zoom it)` placeholders. `settle('tree')` continues waiting through failures. `close()` aborts the shared signal and waits for busy promises, so a noncooperative compressor can prolong shutdown. Sources: [memory scheduler/build/settle](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/memory.ts), [production compressor](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/compactor.ts).

**optchat-durable:** summarization phases and retry state are persisted Pi tasks. Large leaves build sequentially; ready parents can run with the next leaf, up to eight jobs. Short leaves/concatenations avoid model calls. Defaults: five size attempts, three provider-failure attempts, ten-second retry delay. Shortest nonempty summary is published after size attempts even if oversized, explicitly flagged. Failed preparation fails the request rather than supplying placeholders; an otherwise complete view over the hard budget fails preparation. An interrupted provider call may be repeated/billed after recovery; durable tasks do not imply exactly-once external actions. Sources: [task implementation](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/memory/tasks.ts), [defaults](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/config.ts), [request preparation](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/request-task.ts), [recovery limitations](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/docs/reference/conformance.md).

Neither TS commit path performs semantic validation that a returned summary preserves author attribution or required tool/source facts. Their prompts request faithful attribution, but a nonempty fabricated summary can still be accepted structurally. This should be tested with deliberate faulty providers before reuse. Sources: the two build implementations above; [pi prompts](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/prompts.ts), [durable prompts](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/prompts.ts).

## Views, cutoffs and durability

Both implement aligned binary nodes, corrected sibling priority based on the pair's last record, main high/low sawtooth 128k/64k, and smaller compactor target 32k/16k. Their byte accounting and recovery differ materially:

- pi-optchat's measured view size adds flattened node text bytes, **excluding address prefixes, line separators and `<chat>` wrappers**. A reported size within budget need not imply rendered wire text within it. Only the main partition is saved; its merging flag/unfinished low target is not. Compactor state is seeded from main and refitted on reopen, so its exact live prefix is not durably restored. A cutoff stops before the first crossing compactor part, potentially omitting earlier records inside that part; unfinished parts appear as placeholders.
- optchat-durable counts complete rendered wire bytes including markup, saves both partitions and unfinished low targets. A historical compactor cutoff recursively splits crossing nodes in a temporary projection to retain the complete earlier summarized prefix; preferred quarter-budget may be exceeded up to main hard ceiling. It never invents an unfinished placeholder.

Sources: [pi Sawtooth/load/save/compactionView](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/memory.ts), [durable wire rules](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/memory/tree.ts), [durable stored batch/cutoff rules](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/memory/store.ts), [durable persisted view schema](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/memory/documents.ts).

pi FileStore fsyncs append records and atomically replaces/fsyncs views; damaged JSON rows are skipped with warnings, then core rejects a noncontiguous original log. Its file-size writer detection is not a substitute for concurrent ownership locking; raw `Memory` integration must provide single-writer ownership. Pi host uses profile locks; custom distributed storage must fence expired leases itself. Async `append()` returns an in-memory entry before storage promise settles, so that return is not a durable admission receipt. Durable `enqueue()` commits an idempotent request document/task transaction first; same ID+text recovers, changed text rejects. Its standalone wrapper acquires a SQLite OS-backed writer lock and fsync JSONL; SDK host owns storage and exclusive access. Configuration/model/budget changes against existing prepared storage reject rather than silently migrate. Sources: [pi writes/lease](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/store.ts), [pi append](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/memory.ts), [durable receipts](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/controller.ts), [durable app startup](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/app.ts), [writer lock](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/writer-lock.ts), [storage contract](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/storage-contract.ts).

## Visibility and caching

pi core exposes change notifications, pending/active, progress/retry delay, last error and tree/log/view. It has **no core usage or per-attempt payload API**. App `UsageLedger` persists numeric input/output/cache-read/cache-write/cost by main/subagent/compactor/import; stable main message IDs deduplicate replay. Malformed/missing fields are excluded with an incomplete-total warning. There is no explicit known-vs-unknown cache coverage denominator, and normalized provider zero is indistinguishable from measured zero at this layer. Transport exceptions before `onUsage(reply)` may leave attempted spending unrepresented. Sources: [core](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/memory.ts), [usage](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/usage.ts), [compressor callback](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/compactor.ts).

Durable public request inspection exposes frozen view and receipt; status exposes memory/errors, recent receipts, **harness-wide** usage/live tasks. Native Pi objects remain public for native events/task inspection. This is not a library-owned UI-ready per-attempt record of exact provider wire payload plus usage coverage. Providers/hooks may add that instrumentation. Its cache evaluation docs explicitly distinguish unknown usage, simulated counts and measured provider rates; no funded continuous-cache result is claimed. Sources: [controller](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/controller.ts), [SDK ownership](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/docs/guides/sdk.md), [cache claims and study limits](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/docs/reference/cache.md).

Both split view into stable four-line blocks and coordinate cold Anthropic prefixes. **pi cachePayload deletes existing host system/tool/recent-message cache markers and replaces them with its view/end policy.** Durable preserves host marks/retention/opt-out and may skip its additional mark when slots or TTL policies conflict. Both use tool-free separate summarizer instructions, so neither shares main-role system/tools with compactor as the reference cache recipe proposes. pi host can refresh an exceptionally long turn mid-run, replacing the earlier captured view; durable SDK persists one frozen view per queued user request and expects exclusive conversation admission through controller methods. Sources: [pi cache override](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/cache.ts), [pi context/refresh](https://github.com/jonaslsaa/pi-optchat/blob/2bdbd4df63c696fabc06ee9bc616245083069097/src/index.ts), [durable cache preservation](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/src/cache.ts), [durable cache limitations](https://github.com/kevinqz/optchat-durable/blob/6b2285cf88ab803d859a0efb038610f2a003ff50/docs/reference/cache.md).

## Adoption gates for the proposed TypeScript project

1. Decide whether the host owns an existing agent loop or intentionally adopts Pi Durable; that separates the two candidates.
2. Probe exact tree/view execution with fixed compressor responses, concurrency, restart, failed attempts, cutoff boundaries and Unicode markup. Compare invariants rather than requiring identical summaries from different prompts.
3. Require an explicit ready/pending/failed contract, durable append receipt, bounded retries, exact request/attempt capture and known/unknown usage coverage if matching our current memory requirements.
4. Run semantic fidelity cases for author corrections, tool facts, identifiers and source-shaped instructions; prompt promises are insufficient.
5. Measure real provider cache and billing only in a separately authorized live study with identical providers/models, frozen corpus and raw usage. Synthetic prefix overlap is not measured cache savings.
