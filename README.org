#+title: SlopChat

SlopChat is a headless Emacs Lisp agent with durable chat memory. It combines
Ouro's self-written agent loop with Victor Taelin's hierarchical memory design.
Codex app-server provides model access through an existing ChatGPT subscription;
the Lisp agent owns execution and memory.

A chat directory identifies one conversation. Its history and memory survive
server restarts; the agent bootstraps its Lisp loop again on restart. Interrupted
tasks do not resume automatically.

* Run

Requirements: Emacs 30+, Codex CLI authenticated with a ChatGPT account, Linux
=flock= and =truncate=, Python 3 for the server launcher, and Bun for the terminal
client. Check authentication with =codex login status=. An API key is not required.

From the repository root, start the server:

#+begin_src sh
./scripts/chat-server
#+end_src

The launcher restarts abnormal exits with bounded backoff and logs exit codes
and signals in =.chats/main/supervisor.log=. Ctrl+C stops it. Saved memory survives;
interrupted turns are not replayed. Pass another chat directory as its argument.

In another terminal, from the same repository root:

#+begin_src sh
bun install --cwd ui
./scripts/chat-tui
#+end_src

Enter sends; Ctrl+Enter inserts a newline. Sending while the agent works steers
its current turn. Ctrl+C clears input; on empty input press twice within one
second to close the client. The server keeps running.

For another chat, start its server with that directory and run
=./scripts/chat-tui /absolute/chat/directory=. Only one server can own a chat.

Optional Python 3 client:

#+begin_src sh
python3 scripts/slopchat.py .chats/main 'Hello!'
python3 scripts/slopchat.py --help
#+end_src

* Update the terminal client

Source changes take effect when the TUI client is relaunched with
=./scripts/chat-tui=. There is no hot view replacement or publication polling.
The Lisp server runs independently and does not need restarting.

** Ordinary commands wait in Lisp
Use =(slopchat-run-command COMMAND WORKDIR TIMEOUT-MS)= for ordinary commands.
It waits responsively via bounded process-output waits, defaults to 120 seconds,
returns bounded output and exit code, and reports =timed-out= after cancellation.
Explicit background work retains exec/write-stdin sessions. Neither mode wakes
a finished model turn automatically.

* Standalone memory module

The application's memory is behind the =unii-memory-*= interface. The four
=unii-memory*.el= implementation files can be loaded without SlopChat or Codex;
a summarizer is supplied as an asynchronous backend. The application owns its
turn loop and provider adapter, while memory owns its journal, tree, views,
compaction queues and usage accounting.

See [[file:docs/memory-module.org][the interface and backend contract]] for API,
ownership, truthful cache visibility and independent package/socket checks.

** Developing the dependency
Clone with =git clone --recurse-submodules=, or run
=git submodule update --init --recursive= in an existing clone.
The application loads =vendor/unii-memory= directly. Edit its sources there;
no package installation or release is needed. Use a fresh Emacs process to test.
Commit and push library changes inside that directory, then commit its updated
Git pointer in SlopChat. Before editing a pinned checkout, use
=git -C vendor/unii-memory switch main=.
